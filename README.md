# usb-cable-info

Что за USB-C кабель воткнут в Mac: паспорт из e-marker'а (скорость, ток, вольтаж, мощность, длина),
реально поднятая связь и профили зарядки.

## Как проверять кабель

**Оба конца кабеля — в два порта Mac (петля).** Один порт становится источником питания, подаёт VCONN
и читает e-marker; Thunderbolt/USB4 поднимается сам с собой — это реальная скорость кабеля,
а не предел устройства на другом конце. Mac при этом «заряжает сам себя» 15 Вт — безвредно.

Другие случаи:
- кабель + устройство (iPhone, SSD) — метка читается, связь = минимум из кабеля и устройства;
- кабель + зарядка — метку читает зарядка, не Mac; видны только профили зарядки
  (если она предлагает > 3 А — значит, увидела 5-амперную метку);
- пустой кабель одним концом — Mac его не опрашивает (нет Rd на том конце → нет VCONN).

Кабели без e-marker'а (дешёвые 3 А USB 2, все USB-A ↔ C) о себе ничего не сообщают — для них
только факт связи в петле. Метка — это то, что кабель о себе заявляет; проверка делом — связь в петле.

## Сборка

```bash
./build.sh                  # → /Applications/USB Cable.app + ~/.local/bin/usb-cable
open "/Applications/USB Cable.app"
usb-cable --once            # отчёт в терминал (exit 1, если ничего не подключено)
```

Строка меню: иконка кабеля; 15 с после подключения рядом сводка «40G · 240W», полный отчёт — в меню
(«Скопировать отчёт», «Запускать при входе»). Обновление по событиям IOKit, без опроса.

## Откуда данные

IORegistry, ветка `IOPort` (Apple Silicon): `Port-USB-C@N` →
`CC/SOP'` (Discover Identity кабеля, VDO: ID Header, Cert, Product, Cable VDO1[, VDO2 у активных]),
`CC/SOP` (устройство на том конце), `USB2`/`USB3`/`CIO` (линки), `Power In/USB-PD`
(`PowerSourceOptions`, `WinningPowerSourceOption`). Скорость TB/USB4 — `system_profiler -json
SPThunderboltDataType` (receptacle_id = номер порта). VDO — 4 байта little-endian.
Снимки IORegistry с реальными подключениями — в `in/` локально (snap-1 iPhone, snap-2-charger 100 Вт PD, snap-4 петля); в репо не входят — в них серийники.

## Грабли

- **Частый `ioreg -l` по портам рвёт EPR-зарядку.** 2026-11-25 с зарядкой 140 Вт (28 В): `ioreg -w0 -l -c
  AppleHPMInterfaceType10` раз в секунду → обрыв PD-контракта (Plug Event Count +2 за 45 с, IsCharging
  мигает); в покое — 0. Вероятно, ioreg читает свойства родительских узлов HPM, и контроллер порта
  не успевает с EPR keep-alive. `usb-cable --once` (читает только узел порта и его детей) раз в 2 с ×15 —
  0 обрывов. Поэтому утилита читает реестр только по событиям IOKit и при открытии меню, без опроса.
  Для отладки следить по событиям, а не поллингом `ioreg -l`.
